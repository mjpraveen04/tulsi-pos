2Option A – use the hosted application

No installation is needed. Open https://tulsi-web.onrender.com in a current browser (Chrome, Edge, Firefox or Safari) on a laptop or tablet and sign in with one of the accounts in Section 1.1.

The first request can take 30–60 seconds. The application runs on free hosting plans: the API goes to sleep after 15 minutes without traffic and is woken by the next request. If the login screen shows no names or a loading message, wait a minute and reload the page. After that, the application responds normally.

The hosted instance runs exactly the code of the main branch: Render rebuilds it automatically on every push. It uses its own PostgreSQL database on Neon, so sales and stock changes made there are stored permanently and are visible to everyone who uses the demo. Section 7 describes how this deployment is set up.

3Option B – install locally with Docker Compose

The whole system – database, API and web front end – runs as three containers started with one command (NFR-14). Nothing else needs to be installed on the computer.

3.1 Prerequisites

Docker with Compose v2Docker Desktop 4.x (Windows, macOS) or Docker Engine 24+ with the Compose plugin (Linux). Check with docker compose version.
Memory and diskAbout 2 GB free RAM for Docker and 1.5 GB disk for the images.

Git (optional)To clone the repository. Alternatively use the code zip from the submission or GitHub’s Download ZIP.

3.2 Steps

  1. Get the code. 
    git clone https://github.com/mjpraveen04/tulsi-pos.git
cd tulsi-pos
    or unzip MysoreJagannath-Praveen_10251728_PSE_Submission_Code.zip and open a terminal in the unzipped folder.
  2. Start Docker Desktop and wait until it reports that it is running.
  3. Optional – create a configuration file. Every setting has a safe default, so this step can be skipped. 
    cp .env.example .env        # Windows PowerShell: copy .env.example .env
  4. Build and start all three containers: 
    docker compose up --build
    The first build downloads base images and takes a few minutes; later starts take seconds. The API log shows these three lines when it is ready: 
    [entrypoint] applying Alembic migrations...
[entrypoint] seeding demo data (idempotent)...
[entrypoint] starting uvicorn...
  5. Open http://localhost:5173 and sign in, for example as Anita R. with PIN 1234.

To run the stack in the background instead, use docker compose up -d --build; docker compose logs -f api then shows the API log.

3.5 If a port is already in use

Choose other host ports in .env or directly on the command line. The containers talk to each other inside Docker, so only the published ports change:

WEB_PORT=5180 API_PORT=8010 DB_PORT=5440 docker compose up --build

The application is then at http://localhost:5180. A local PostgreSQL installation is the most common cause of a conflict on port 5432.

After changing .env, restart with docker compose up -d. Product photos are stored in the database, so no extra file storage needs to be configured or backed up.

5Running the automated tests

The 120 backend tests run against a real PostgreSQL database, because the concurrency and rollback release gates need real row locks and a real CHECK constraint. The test setup creates a separate database tulsi_pos_test and migrates it with Alembic; the application’s data is not touched.

Additional prerequisite: Python 3.11 (3.12 also works).

docker compose up -d db                       # the database container is enough
cd backend
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt     # Windows: .venv\Scripts\pip ...
PATH="$PWD/.venv/bin:$PATH" .venv/bin/python -m pytest -q

Expected result: 120 passed in about two minutes. Only the six release gates: add -m gate (about 4 s).

Two things that make every test fail with an error: (1) the virtual environment is not on PATH – the test setup calls the alembic command and reports FileNotFoundError: alembic; (2) the database runs on another port than 5432. In that case pass its address:
TEST_DATABASE_URL="postgresql+psycopg2://tulsi:tulsi@localhost:5440/tulsi_pos_test" before the command.

The front end has no unit tests (TD-02); its correctness against the API is checked by the TypeScript compiler. npm run build in frontend/ type-checks every file first and fails on any mismatch with the API types.

6Developer mode without Docker

For changing the code, the API and the front end can run directly on the computer with automatic reload. The database still runs in Docker. Additional prerequisites: Python 3.11 and Node.js 20 or newer.

# terminal 1 – database
docker compose up -d db

# terminal 2 – API on http://localhost:8000
cd backend
.venv/bin/alembic upgrade head
DATABASE_URL="postgresql+psycopg2://tulsi:tulsi@localhost:5432/tulsi_pos" \
  .venv/bin/uvicorn app.main:app --reload

# terminal 3 – front end on http://localhost:5173
cd frontend
npm install
npm run dev

The Vite development server forwards /api and /media to http://localhost:8000; set VITE_API_TARGET to use another address. Stop the Docker web and api containers first if they occupy ports 5173 and 8000. The alembic and uvicorn commands also need DATABASE_URL when the database is not on port 5432.

7Cloud deployment (Render + Neon)

The hosted application is deployed from the file render.yaml (a Render Blueprint) in the repository. It defines two services built from the same Dockerfile and front end as the local installation; the database is a free PostgreSQL project on Neon, because Render’s free database is deleted after 30 days.

PartProvider and planConfiguration
tulsi-apiRender web service, Docker, freeBuilt from backend/Dockerfile; health check /api/health; environment variables from render.yaml; JWT_SECRET generated by Render; DATABASE_URL entered by hand
tulsi-webRender static site, freenpm ci && npm run build; publishes dist/; rewrites /api/* and /media/* to the API and all other paths to index.html
DatabaseNeon PostgreSQL 18, free, EU regionConnection string with sslmode=require

7.1 Deploying a new copy

  1. Fork or push the repository to your own GitHub account.
  2. At neon.tech create a project and copy the connection string. Change its start from postgresql:// to postgresql+psycopg2:// and keep ?sslmode=require at the end.
  3. At render.com choose New → Blueprint, connect the repository and paste the string as DATABASE_URL when asked. Render creates both services and starts the first build.
  4. Render assigns the API a host name such as tulsi-api-xxxx.onrender.com. If it differs from the one in render.yaml, change the two rewrite destinations there and push the change.
  5. Open the address of the tulsi-web service. Migrations and demo data are applied by the API on its first start.

Every later push to main redeploys both services automatically. Free-plan limits: the API sleeps after 15 minutes without traffic (first request 30–60 s).

8Using the application – first steps

8.1 Sell (cashier or manager)

  1. On the Register, filter by category if needed and tap a photo card to add the item to the order. Tap again or use + / − to change the quantity. A card cannot be added beyond its stock; sold-out items are greyed out.
  2. The order panel shows subtotal, 5 % GST and total. Tap Charge.
  3. Cash: enter the amount received; the change is shown, and Payment received becomes available once the amount covers the total. UPI: the customer scans the QR code; after checking their phone, tap Mark paid.
  4. The receipt shows the bill number and can be printed. Stock is reduced at the same moment.

8.2 Manage (manager only)

  • Inventory: add or edit products (name, category, price, reorder level, photo); Receive or Remove stock – every change appears in the stock activity list with the user and time; archive products that are no longer sold.
  • Orders: search bills by date or bill number, open a receipt, and see the day’s total.
  • Staff: add staff with name, role and PIN, reset a PIN, or deactivate an account. The last active manager cannot be deactivated.

Cashiers see only the Register and their bill history. The server checks the role of every request, so a cashier cannot reach manager functions even by calling the API directly (HTTP 403).
